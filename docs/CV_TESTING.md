# 🧪 Методология CV-тестирования браузерных скриншотов

## Обзор

Валидация UI веб-приложения проводится **исключительно визуальным анализом реальных браузерных скриншотов** с помощью компьютерного зрения (CV). Программные проверки DOM/JS не заменяют визуальный анализ — они проверяют наличие элементов в коде, но не их визуальную корректность.

---

## Алгоритм тестирования

### 1. Подготовка тестовой среды

```
Запуск мок-API сервера → Запуск headless Chrome → Навигация на страницу
```

**Компоненты:**
- **Мок-API сервер** (`mock_server.mjs`) — Node.js HTTP сервер, эмулирующий бэкенд API:
  - `GET /api/v1/health` — healthcheck
  - `POST /api/v1/parse` — LLM парсинг промта (возвращает анализ, декомпозицию, референсы, вопросы)
  - `POST /api/v1/orchestrator/execute` — оркестратор (возвращает задачи агентов)
  - `POST /api/v1/generate` — генерация GLB модели
  - Статические файлы — раздача `index.html` и ресурсов

- **Headless Chrome** — Playwright + Chromium для эмуляции реального браузера:
  ```
  executablePath: '/path/to/chrome'
  args: ['--no-sandbox', '--enable-webgl', '--use-gl=swiftshader']
  ```

### 2. Взаимодействие с UI

Для каждого промта выполняется **реальное пользовательское взаимодействие**:

```javascript
// 1. Открытие страницы
await page.goto('http://127.0.0.1:8080/index.html', { waitUntil: 'networkidle' });

// 2. Заполнение поля ввода (реальный DOM-инпут)
await page.evaluate(async (text) => {
  const inp = document.getElementById('msgInput');
  inp.value = text;
  inp.dispatchEvent(new Event('input', { bubbles: true }));
  await sendMessage();
}, promptText);

// 3. Ожидание полного pipeline (парсинг → декомпозиция → генерация)
await page.waitForTimeout(8000);

// 4. Скролл чата для показа всех элементов
await page.evaluate(() => {
  const chat = document.getElementById('chatMessages');
  chat.scrollTo({ top: chat.scrollHeight, behavior: 'instant' });
});

// 5. Сохранение скриншота
await page.screenshot({ path: 'screenshots/test_name.png', fullPage: false });
```

**Критично:** Используется `page.evaluate()` + `sendMessage()` а НЕ `page.click('#sendBtn')`, т.к. click может не сработать в headless режиме.

### 3. Визуальный анализ через CV

Каждый скриншот анализируется моделью компьютерного зрения:

```bash
bash ~/.openclaw/skills/mimo-omni/mimo_api.sh image \
  screenshots/test_name.png \
  "Детально опиши что видно. Есть ли: 1) Сообщение пользователя 2) Анализ запроса 3) Декомпозиция 4) Референсы 5) Уточняющие вопросы 6) 3D-модель. Релевантно ли промту?" \
  --max-tokens 65536
```

**Что проверяет CV:**
- Наличие и корректность каждого UI-блока
- Релевантность содержимого промту
- Видимость 3D-модели в превью
- Отсутствие визуальных артефактов

### 4. Проверка адаптивности

Для каждого разрешения делается отдельный скриншот:

| Разрешение | Устройство | Что проверять |
|-----------|-----------|---------------|
| 1920×1080 | Desktop | Все элементы видны, чат корректен |
| 375×812 | Mobile | Input виден, меню работает, не обрезано |
| 768×1024 | Tablet | Чат-панель видна, input доступен |

### Формат отчёта

Для каждого промта проверяется 7 параметров:

| # | Параметр | Метод проверки |
|---|----------|---------------|
| 1 | Сообщение пользователя видно | CV: ищем текст промта в чате |
| 2 | Анализ запроса (reasoning) | CV: ищем "Анализ вашего запроса" + релевантные параметры |
| 3 | Декомпозиция на шаги | CV: ищем "Декомпозиция задачи" + нумерованные шаги |
| 4 | Референсы | CV: ищем "Референсы" + карточки |
| 5 | Уточняющие вопросы | CV: ищем "Уточняющие вопросы" + кнопки ответов |
| 6 | 3D-модель в превью | CV: ищем объект в области просмотра (не заглушку) |
| 7 | Релевантность промту | CV: содержимое соответствует запросу |

## Типичные баги, которые ловит CV-тест

### 1. JS syntax error → весь UI мёртв
**Симптом:** CV видит только заглушку, нет сообщений в чате
**Причина:** Ошибка в JS блокирует все функции (sendMessage, addMessage и т.д.)
**Пример:** Неэкранированные `'` в inline-обработчиках `onmouseover`

### 2. HTML экранируется → сырой текст вместо карточек
**Симптом:** CV видит `<div class="reasoning-card">` как текст
**Причина:** `esc()` применяется к HTML-контенту ассистента

### 3. return прерывает pipeline → генерация не запускается
**Симптом:** Есть reasoning и вопросы, но нет3D-модели
**Причина:** `sendMessage()` делает `return` после показа вопросов

### 4. Canvas 0×0 →3D не рендерится
**Симптом:** GLB загружен (100%), но канвас чёрный
**Причина:** `init3D()` вызывается когда `canvas` имеет `display:none`

### 5. Mobile layout сломан → input за пределами экрана
**Симптом:** CV не видит поле ввода на мобильном скриншоте
**Причина:** Нет кнопки открытия чат-панели, `chat-panel` скрыт по умолчанию

## Воспроизведение

### Быстрый старт

```bash
cd AI_Arhitector

# 1. Запустить мок-сервер
node mock_server.mjs &

# 2. Запустить скриншоты + CV анализ
node take_screenshots3.mjs

# 3. Проанализировать конкретный скриншот
bash ~/.openclaw/skills/mimo-omni/mimo_api.sh image screenshots/cv_test/bathroom.png "Опиши что видно"
```

### Добавление нового промта

1. Добавить промт в массив `PROMPTS` в `take_screenshots3.mjs`
2. Запустить скрипт
3. Проанализировать скриншот через `mimo_api.sh`
4. Проверить все 7 параметров
5. Занести результат в отчёт

## v11.0.0 — Расширенная методология верификации

### Полный E2E сценарий: промт → 3D модель

Для v11.0.0 тестируется полный pipeline:

```
Промт в чат → sendMessage()
  → /api/v1/orchestrator/execute
    → ParserAgent (Gemini/OpenRouter)
    → ClarificationEngine.analyze()
      → если clarification_needed → показать вопросы
      → пользователь отвечает → /api/v1/orchestrator/resume
    → Route → Pre-agents (concept, style, furniture, lighting)
    → Geometry + Texture (parallel)
    → Mid-agents (landscape, mep, structural)
    → Render (Cycles CPU/HDRI)
    → Quality check
    → Export (GLB)
    → Post-agents (compliance, financial)
```

### Защита от галлюцинаций

**Ключевой принцип: каждый факт — с доказательством.**

| Защита | Реализация |
|--------|----------|
| Логи API | Каждый HTTP-запрос/ответ логирую. Не "я проверил", а "вот JSON ответ" |
| Скриншоты | Каждый шаг — скриншот. Не "выглядит хорошо", а "вот скрин, вот анализ vision" |
| Автоматические asserts | `assert resolution >= 3840` — если не прошло, пишу ❌, не ✅ |
| Vision-модель как судья | mimo-omni анализирует скриншот БЕЗ контекста — описывает что видит |
| Публикация доказательств | Все скрины, логи, JSON — в TEST_REPORT.md |
| Не доверяю себе | Если написал "✅" — требую лог/скрин. Нет доказательства = "⚠️ не проверено" |

**Пример:**
```
❌ Вранье: "Джакузи присутствует на рендере"
✅ Проверка:
   1. Скриншот → /screenshots/render.png
   2. Vision: "Ванная комната. Видна ванна белого цвета. Джакузи НЕ видно."
   3. Вывод: ❌ Джакузи отсутствует. Нужно исправить furniture_agent.
```

## Ограничения

| Ограничение | Описание |
|-------------|----------|
| Headless WebGL | Three.js может не рендерить в headless Chrome (зависит от GPU/SwiftShader) |
| Мок-сервер | Не возвращает реальную3D-модель — только минимальный GLB-треугольник |
| CV точность | MiMo Omni может пропустить мелкие элементы или неверно интерпретировать |
| Тайминг | `waitForTimeout` — фиксированное ожидание; в реальном проекте лучше waitForSelector |
