## 1. Недостатки микро-сервисной архитектуры и потенциал улучшения

### Текущее состояние
Архитектура: 5 Render аккаунтов (Gateway + 2 Blender + LLM + 16K tiled Blender + backup LLM).

### Критические проблемы

| # | Проблема | Детали | Влияние |
|---|----------|--------|---------|
| 1 | **Фейковые микросервисы** | Gateway, LLM, Blender все импортируют общий `shared/` через `sys.path.insert`. Это один монолит на трёх портах | Баг в shared/ ломает ВСЕ сервисы |
| 2 | **Двойной code path** | `server.py` (монолит, локальный Blender) vs `gateway/app.py` (прокси через HTTP) — разное поведение | Баги проявляются только в одном режиме |
| 3 | **9 сервисов declared, 3 работают** | В config есть URL для 10 сервисов (llm, blender, geometry, ifc, ml, data, cad, freecad, vectordb, graphdb). Реально работают только 3 | Мёртвый код, заблуждение при оценке |
| 4 | **Jobs in-memory** | `_orchestrator_jobs: dict = {}` — рестарт = потеря всех задач | Потеря работы пользователей |
| 5 | **Pipeline последовательный** | parse → geometry → texture → render → export. Geometry и Texture независимы и могут быть параллельно | 2× медленнее чем могло бы быть |
| 6 | **Нет retry per-step** | Один шаг упал → весь pipeline failed | Хрупкость |
| 7 | **Нет таймаутов per-step** | Texture может зависнуть без обнаружения | Ресурсный лик |
| 8 | **3 копии index.html** | `index.html`, `frontend/`, `gateway/frontend/` — рассинхронизация | Баги UI |

### Рекомендации по улучшению

- **Переход на реальные микросервисы**: убрать `sys.path.insert`, каждый сервис — независимый Docker-образ с own dependencies
- **Redis для jobs persistence** с TTL
- **Параллельные шаги** через `concurrent.futures.ThreadPoolExecutor` (geometry + texture одновременно)
- **Exponential backoff retry** per-step с таймаутами
- **Единая точка входа для frontend** — одна копия, symlink или CDN
- **DAG-based pipeline** вместо жёстко зашитой последовательности

## 2. Генерирует ли сервис 16K качество мебели в интерьере?

### Вердикт: НЕТ (де-факто)

**Что заявлено:**
- 15360×8640 = 132 мегапикселя, Cycles 2048 samples, tiled rendering 4×3 = 12 тайлов
- Pipeline: LLM → Geometry → Texture → Blender Cycles → Quality check

**Что есть на скриншотах:**
- **IMG_1430** (кухня хайтек): сгенерировался экстерьер дома вместо интерьера. Нет мебели вообще
- **IMG_1432** (ванная с джакузи): сгенерировался экстерьер дома. Полное несоответствие
- **IMG_1429** (дизайн детской): ошибка `Cannot uninitialized variable`, пустой viewport

**Проблемы с интерьерной генерацией:**
1. **Тип генерации неверно определяется** — LLM парсер определяет "интерьер" как "здание"
2. **Blender недоступен** — fallback на "браузерный рендер" = упрощённые примитивы
3. **Interior 16K хардкодит 4K** — `_generate_interior()` не поддерживает tiled rendering
4. **Мебель = 7 типов box** — нет каталога реальной мебели
5. **Текстуры = noise texture** — нет image-based PBR

**Время рендера 16K:**
- CPU-only: ~12 тайлов × 10 мин = ~2 часа
- GPU (nvidia-docker): ~15-20 минут
- На бесплатном Render: невозможно (512MB RAM)

## 3. Сколько референсов к каждому промту анализирует ИИ-агент?

### Вердикт: 0 референсов

**Что есть в коде:**
- `vectordb-service/` — обёртка над Qdrant (190 строк, CRUD заглушка)
- `graphdb-service/` — обёртка над Neo4j (209 строк, CRUD заглушка)

**Чего НЕТ:**
- Модуля поиска референсных изображений
- Интеграции с архитектурными базами (ArchDaily, Dezeen, Pinterest)
- Embedding модели для архитектурных изображений
- Image-to-image similarity search
- RAG pipeline (промт → embedding → nearest refs → context)
- Style transfer из референса

**Что нужно для работы с референсами:**
1. Dataset референсных изображений (по стилям, типам зданий)
2. CLIP/SigLIP embedding для семантического поиска
3. Vector DB индексация (Qdrant)
4. RAG pipeline: промт → embedding → nearest референсы → контекст для LLM
5. Style transfer: взять стиль референса + размеры из промта

**Вывод:** Агент НЕ анализирует референсы. Генерация идёт "вслепую" — только по текстовому промту.

## 4. Генерирует ли сервис 16K экстерьер дома?

### Вердикт: ТЕОРЕТИЧЕСКИ ДА, ФАКТИЧЕСКИ НЕТ

**Архитектурно поддержка есть:**
- `shared/tiled_render.py` — разбивает 15360×8640 на 12 тайлов
- `/api/v1/render/16k` endpoint в blender-service
- QualityAgent проверяет разрешение ≥15360×8640, файл ≥8MB

**На практике (скриншоты):**
- IMG_1432, IMG_1430, IMG_1431 — все экстерьеры сгенерированы в **браузерном viewport** (Three.js low-poly), не через Blender Cycles
- Качество: примитивные блоки, плоские текстуры, нет освещения, нет детализации
- Размер рендера: viewport resolution (видимо ~1920×1080), не 16K

**Почему не работает:**
1. Blender-сервис недоступен на бесплатном Render (512MB RAM, таймаут 300s)
2. Fallback на "браузерный рендер" = Three.js примитивы
3. Cycles рендер на CPU без GPU = часы ожидания
4. Нет tiled rendering в реальном pipeline (только в коде)

## 6. Какие стандарты каркаса, стройки, электрики, коммуникаций, воздуховодов, канализации, стен интегрированы?

### Вердикт: НИКАКИЕ стандарты не интегрированы

**Что генерируется сейчас:**
- Стены — box (parallelepiped), без конструктивной системы
- Окна — декоративные cubes, не реальные оконные блоки
- Двери — плоские cubes без дверной коробки
- Лестница — 12 одинаковых ступеней без учёта уклона
- Кровля — примитивные геометрические формы

**Что НЕ учитывается:**

| Область | Стандарты | Статус |
|---------|-----------|--------|
| **Каркас/Конструкции** | СП 20.13330 (нагрузки), Eurocode 2/3 | ❌ Нет |
| **Стены** | СП 54.13330 (жилые здания), U-value | ❌ Нет |
| **Электрика** | ПУЭ, IEC 60364 | ❌ Нет |
| **Коммуникации** | СП 30.13330 (водоснабжение), СП 32.13330 (канализация) | ❌ Нет |
| **Воздуховоды** | СП 60.13330 (отопление/вентиляция) | ❌ Нет |
| **Канализация** | СП 32.13330 | ❌ Нет |
| **Эвакуация** | СП 1.13130 | ❌ Нет |
| **Теплозащита** | СП 50.13330 | ❌ Нет |
| **Окна** | ГОСТ 30733 | ❌ Нет |
| **Чертежи** | ГОСТ 21.501 | ❌ Нет |
| **IFC/BIM** | IfcOpenShell есть, но IfcPropertySet пустой (нет U-value, fire resistance, load-bearing) | ⚠️ Заглушка |

**Интеграция с промтами:** В промтах LLM парсера упоминаются стили (modern, classic, loft и т.д.) и материалы (brick, concrete, wood), но **без привязки к строительным нормам**. Это чисто визуальные параметры, не инженерные.

## 7. Согласованы ли вкладки 3D, план комнат, разрез между собой? Есть ли премиальное качество?

### Вердикт: НЕТ согласованности, НЕТ премиального качества

**Что видно на скриншотах:**

| Вкладка | Статус | Качество |
|---------|--------|----------|
| **3D** | Работает (когда нет ошибок) | Low-poly примитивы, нет материалов, нет освещения |
| **Внутри** | Не работает (ошибка uninitialized) | Пустой viewport |
| **План** | Не проверен (нет скринов) | N/A |
| **Разрез** | Не проверен (нет скринов) | N/A |
| **Фасад** | Не проверен (нет скринов) | N/A |

**Проблемы согласованности:**
1. **3D и план** — если план вообще генерируется, он не связан с 3D-моделью (нет единой BIM-модели)
2. **Разрез и фасад** — нет данных о генерации; если генерируются, это 2D-проекции из 3D-примитивов
3. **Нет единой модели** — каждый вид, вероятно, генерируется независимо

**Качество:**
- Геометрия: примитивные кубы и параллелепипеды
- Текстуры: плоские, без нормалей, без PBR
- Освещение: ambient-only, без теней
- Детализация: отсутствует (нет молдингов, фурнитуры, декора)
- Масштаб: есть размерные линии (6м, 8м, 2.8м) — единственное что работает

## 10. Повторяются ли проблемы со скринов сейчас?

### Анализ AUDIT.md (от 2026-08-01) vs скриншоты

**Заявлено как исправленное в Phase 1:**
1. ✅ Удалён `promt_parser.py` (дубликат)

3. ✅ LLM-only парсер с каскадом 7 моделей
4. ✅ Redis кеш

7. ✅ Tiled rendering для 16K
8. ✅ Auth middleware

**НО: скриншоты показывают, что базовые проблемы НЕ решены:**

| Проблема | Статус по AUDIT.md | Статус по скринам |
|----------|--------------------|--------------------|
| Неверное определение типа генерации | Не упоминается | 🔴 Воспроизводится (3 из 5 скринов) |
| `Cannot access uninitialized variable` | Не упоминается | 🔴 Воспроизводится (2 из 5 скринов) |
| Blender недоступен | Не упоминается | 🔴 Воспроизводится (логи на скринах) |
| Fallback на браузерный рендер | Не упоминается | 🔴 Воспроизводится |
| Низкое качество 3D | Phase 2 планирует | 🔴 Не улучшено |

### Ключевые выводы

1. **`Cannot uninitialized variable`** — критический баг, не отражён в AUDIT.md. Воспроизводится на 2 из 5 скринов. Нужен hotfix.

2. **Неверная классификация типа генерации** — LLM парсер определяет "ванная", "кухня", "детская" как building вместо interior. Это проблема в системном промте парсера или в логике `_detect_gen_type()`.

3. **Blender-сервис хронически недоступен** — на бесплатном Render (512MB RAM) Blender не запускается. Fallback на браузерный рендер = примитивное качество.

4. **Phase 1 исправила инфраструктуру, но не функциональность** — аудит фокусировался на Docker, auth, CORS, но не на корректности генерации.
